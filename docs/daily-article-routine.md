# 毎日の自動更新（Claude が1日2回、記事を1本ずつ書いて公開する手順）

Claude Code の定期実行（Routine）が毎日2回（朝 6:52・夕方 18:52、日本時間）このファイルを読んで作業する。1回の実行で書くのは1本。ルールを変えたいときはこのファイルを直せばよい（Routine 側の設定は変えなくてよい）。
AGENTS.md の運営方針・記事追加・デザインのルールがすべて優先する。

## 1日の作業
1. `git pull origin main` で最新にする。`docs/daily-log.md` の直近の記録を読む。
2. 今日の日付と時刻（日本時間）を確認する。12時より前なら「朝」、12時以降なら「夕」の回。log に今日の同じ回の記録がすでにあれば、何もせず終了する（二重公開の防止）。
3. テーマを選ぶ（下の「テーマの選び方」）。
4. 一次情報（メーカー・公式ドキュメント・公的機関）で事実を確認する。WebFetch で開けないサイトは WebSearch の結果やメーカーの別ページで確かめる。**記事の柱になる事実が確認できないテーマは書かない**。次の候補に替える。
5. 記事を書く（下の「書き方」）。`src/content/articles/<slug>.md`、date は今日（日本時間）、draft: false。
6. 表紙を作る：`design/thumbnails/<slug>.svg` を既存のSVG（例：meta-muse-wonder.svg）を参考に作り、`node scripts/export-thumbnail.mjs <slug>` → 書き出したPNGを開いて文字の欠け・重なりを確認して直す → `node scripts/image-variants.mjs`。依頼文の条件は docs/thumbnail-prompt.md。coverAlt には「イメージイラスト」と入れる。
7. `npm ci`（node_modules がない場合）→ `npm run build` を成功させる。dist/articles/<slug>/index.html ができていること、本文の内部リンク先が実在することを確認する。
8. `docs/article-queue.md` の該当行を「公開済み」に移し、`docs/daily-log.md` に1行追記する。
9. 作業ブランチにコミットして push し、`git fetch origin main && git merge-base --is-ancestor origin/main HEAD` が通れば `git push origin HEAD:main` で公開する。通らなければ `git pull origin main` で取り込んでビルドし直してから公開する。
10. 最後のメッセージに、公開した記事のタイトル・URL（https://ochanote.com/articles/<slug>/）・確認した主な情報源・気になった点を短く書く。

## 公開しない（下書きで止める）とき
次のどれかに当たる場合は公開しない。記事は draft: true でコミットし、log に「下書き」と理由を書いて、main へは log と下書きだけを反映する。
- 柱になる事実、価格、日付が公式で確認できなかった
- ビルドが通らない、表紙が書き出せない
- 同じテーマ・同じ検索意図の記事がすでにある（その場合は別のテーマに替えるのが先）

## テーマの選び方
- 基本は `docs/article-queue.md` の「候補」の上から。カテゴリが続きすぎないよう、直前の回と違うカテゴリを優先する。
- **AIの新しい発表**：直近3日以内に、主要なAI企業（OpenAI・Google・Anthropic・Meta・Microsoft など）が公式ブログ等で重要な発表をしていれば、その日は候補より優先してよい（週3本まで。同じ発表を2回書かない）。うわさ・リーク・報道だけの情報は扱わない。発表日・提供範囲・日本での提供状況を確認し、「発表」「提供開始」「予定」を区別する。
- 体験（実際に使った感想・写真）が必要なテーマは選ばない。Claude は製品を使えないので、「使ってみた」「レビュー」は書かない。
- 既存の記事と検索意図が重なるテーマは、別の切り口（対象読者・場面）がはっきりしている場合だけ書く。

## 書き方
- です・ます調。一般の読者（大学生も読む）にわかる短い文。見出しはH2から。冒頭の段落で結論を書く。
- 本文はおよそ2,500〜5,000字。比較表か「選び方の分岐図」（flow のHTML。既存記事を参照）を1つ入れる。
- 既存記事へ本文から自然にリンクを2〜3本（`<a href="/articles/<slug>/">タイトル</a>`）。
- 末尾に「## 参照情報」：公式ページをMarkdownリンクで並べ、確認日を書く。
- 価格は原則書かない。書くなら公式の価格で、確認日・税込かどうかを添える。セール価格は書かない。
- 「おすすめ〇選」「最強」「No.1」などの根拠のないランキングは使わない。特定の商品を推す場合は、公式仕様で確認できる条件付きの候補として書く。
- アフィリエイトリンクは入れない（ユーザーが SiteStripe で取得したリンクがある商品だけ、ユーザーの指示で追加する）。
- topics は src/lib/content.ts の一覧から1〜3個。category は gadget / ai / souvenir / furniture / toolbox / life。
- 生成画像は使わない（表紙はSVGのイラスト）。実在商品のロゴや未確認の形は描かない。
